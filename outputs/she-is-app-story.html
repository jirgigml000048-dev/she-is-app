它从哪里来

Gigi 想做一个关于女性内在的产品——不是娱乐向的"测测你是什么星座/甜品"，而是有学术依据的心理测量工具，加上真实女孩的非虚构故事，让用户在测评和阅读中完成某种内在相遇。

这个想法的起点很具体：现有的心理测评内容不稀缺，但把它做得既有质感、又有共情温度、又能在手机浏览器零门槛访问的产品几乎没有。不需要 App，不需要注册才能用，打开即用。

品牌叫「女也 She Is」。「女也」来自古汉字，女字旁，也是"她"的一部分。品牌色是暮色紫 #4A3073——有神秘感、内省感、知识感，刻意绕开粉色系的女性刻板印象。 — 品牌原点

「100位女孩」系列是产品差异化的灵魂：每个真实女孩的故事都配有 AI 生成的封面图、TTS 朗读音频、背景音乐，像一本会呼吸的杂志。

为什么选择纯静态 HTML

这是一个刻意的选择，而不是技术限制。

纯静态 HTML + Tailwind CDN 意味着：没有构建步骤，AI 可以直接看到 DOM 结构并精确修改；部署只要 push 到 GitHub，30 秒后 Netlify 自动上线；用户打开链接即用，没有任何安装门槛。

纯静态 HTML 对 AI 协作极友好：没有编译错误，所见即所得。Claude Code 改完一个文件，F5 刷新就能看到效果。 — 技术选型背后的逻辑

代价是：页面之间没有共享组件，每次要在多个文件里做相同修改。这也是为什么后来需要 scripts/new_story.sh 这样的脚手架——用工具代替手工。

关键决策

先写 VI 规范，再写代码
3 月 24 日，Gigi 发现在没有规范约束的情况下，每次视觉迭代都在返工。于是写下 vi-spec.md，明确了品牌色、字体、组件规范，并列出明确的禁用项。从那天起，视觉才真正稳定。
Supabase Magic Link 优先于 Google OAuth
微信内置浏览器不支持 Google OAuth 弹窗，而目标用户大量在微信里打开链接。Magic Link 通过邮件发送，任何浏览器都能用，成为主要登录方式。
结果页是产品的核心，不是附属
最多 commits 的文件都是测评页（test-hsp.html 28次、test-fmps.html 23次）。结果页不能像报告，要有洞察感，要有「在日常里」「值得想一想」等让用户有共鸣的 section。
故事脚手架化
3 月 26 日，随着故事数量增多，手工复制粘贴模板带来了大量细节不一致的问题。一个 bash 脚本 scripts/new_story.sh 解决了这个问题——一行命令生成完整故事模板，包含所有必要占位符。

VI 规范：克制是最高美学

vi-spec.md 是这个项目最重要的文档之一。它不只规定了"用什么颜色"，更规定了"不能做什么"。

禁用项（The Nopes）
✕Emoji 图标
✕Box-shadow 堆砌
✕饱和弥散渐变
✕Glassmorphism
✕纯黑 / 纯白
✕居中一切
✕圆体字
动效规范
✓只用 transform + opacity，不用其他属性做动画
✓fadeUp: opacity + translateY(16px)
✓easing: cubic-bezier(.25,.46,.45,.94)
留白比装饰更有质感。克制是最高美学。 — VI 规范的设计哲学

人与 AI 是如何协作的

这不是"Gigi 给需求，AI 写代码"这么简单。实际的协作模式是：

Gigi 驱动方向，提出功能需求（往往很具体，包含 HTML 片段或截图参考）；Claude Code 执行实现，一次性完成跨多文件的修改；Gigi 看截图确认，给出精修意见；Claude Code 精修迭代。

项目里大量的 ss-*.png 文件（从 ss-index.png 到 ss-index-v15.png）就是这个循环的物理证据——每一个版本截图，都是一次"见了面"的确认。

Claude Code 最擅长的是批量相似修改：同一个改动要在 10 个测评文件里做时，AI 效率碾压人工。每个测评页都有结果卡片下载功能——是通过一次 session 批量注入 assets/result-card.js 完成的。 — 协作效率的真实体现

VI 规范落地后，Gigi 有一套口头语言：「去掉图标」「呼吸感」「克制」「去掉这个 shadow」。这些关键词 Claude Code 都能准确理解并执行。这种默契不是天生的——是在 15 天的迭代里磨合出来的。

踩过的坑

iOS Safari 渲染 bug

ECR/ERQ 结果页在 iOS Safari 显示异常。根因是 Safari 对某些 flex/grid 属性处理不同。3 月 22 日修复，后来成为每次结果页重构后必做的检查项。

Supabase 初始化时序

登录后 session 无法写入，auth headers 报错。问题是 window.sb 在 DOMContentLoaded 前被使用，加上 CDN 版本不固定导致 breaking change。修复：defer 初始化，直接写 localStorage，固定 CDN 版本。

弥散渐变 → 视觉过度

早期 index 页加了弥散渐变背景，看起来很廉价。根因是没有 VI 规范约束。3 月 24 日写 vi-spec.md 后全站统一，这类问题再没出现。

结果页"上重下轻"

重构后结果页内容集中在顶部，底部空旷。解决方式：加 section 间距，加入「在日常里」「值得想一想」等新内容 section，而不是纯靠 CSS 撑高度。

经验

  • VI 规范要最先写。没有规范的阶段，每次改动都在部分返工。规范不只是"用什么颜色"，更是"不能做什么"。
  • 截图即验收。视觉类改动必须看截图，口头描述容易失真。ss-index-v15.png 的存在不是偶然。
  • 脚手架救生命。重复性内容（故事页）一定要工具化，手工复制粘贴是 bug 的温床。一个 50 行的 bash 脚本可以省掉大量时间。
  • 结果页是产品核心，不是附属。用户测完看到的第一眼决定他们会不会分享。「在日常里」「值得想一想」这些 section 不是装饰，是产品价值的主要载体。
  • 分享路径要在设计期想清楚。html2canvas 结果卡片是社交传播的核心触点，事后加难度远高于一开始设计。
  • Magic Link 优先于 Google OAuth。微信内置浏览器是中国用户的主要入口，Google OAuth 在里面不可用。Magic Link 覆盖了几乎所有场景。
  • 纯静态 HTML 对 AI 协作极友好。没有编译步骤，AI 改完即看，出错也容易定位。这种技术栈在 vibe coding 场景里有独特优势。
