What is She Is?

A self-discovery app for women — and a surprisingly elegant piece of software.

内心的注视是种无畏的爱

"She Is" (女也) is a web app that invites women to explore their inner landscape through a series of psychological assessments. Think of it as a private journaling ritual that speaks the language of modern psychology.

Users take tests on topics like High Sensitivity (HSP), Attachment Style (ECR), Emotion Regulation (ERQ), and Jungian Cognitive Functions. After each test, they get a beautifully designed result card they can save and share.

🧠
Psychological Tests

7 validated assessments across 4 "axes" — Trait, Emotion, Relationship, Motivation.

📖
100 Girls Stories

Real stories from 100 different women. A living archive of inner lives.

🗺️
Inner Map

A personal profile that accumulates your test results into a visual portrait.

💌
Magic Link Login

No passwords. You log in via a link sent to your email — simple and private.

Why this matters for you as a builder

The entire app is a set of plain HTML files with JavaScript inside. There is no build step — no Webpack, no React, no compiling. What you see in the file system is what runs in the browser. This is called a static site, and it makes She Is extremely cheap to host and easy to modify.

The tech stack: what tools were used and why

Every codebase is built from a set of chosen tools. She Is makes deliberate, practical choices.

Tailwind CSS A CSS utility framework. Lets you style things by adding short class names directly in HTML — no separate stylesheet needed for most UI elements.
Supabase A Backend-as-a-Service. Handles user accounts, login emails, and storing test results in a cloud database.
Netlify Functions Serverless functions hosted on Netlify. Used to call the Anthropic AI API (for the narrative/chat features) without exposing the secret API key to users.
localStorage The browser's built-in memory. Test results are saved here first — instant, offline-capable, no network required.
html2canvas A JavaScript library that takes a screenshot of the result card HTML and turns it into a shareable PNG image.

How shared components work

She Is uses a clever pattern to share the navigation header across all pages without copying and pasting the same HTML everywhere. Here's how it works:

HTML <div id="app-header" data-back="true"></div> <script src="assets/header.js"></script>
What this means
Leave an empty placeholder div with id="app-header"
Then load the header.js script
header.js finds that div by ID and fills it with navigation HTML
data-back="true" tells header.js to show a back arrow on this page
Result: every page gets the same header, from one source file
🎯
Why this matters when steering AI

If you want to change the navigation — add a new menu item, change the logo — you change one file (assets/header.js) and every page updates automatically. If you tell AI to "add a notification bell to the header," it should edit header.js, not every individual page. If the AI starts editing each page individually, redirect it.

03

How Data Flows

From a button click to a saved result — tracing information as it moves through the system.

She Is uses two places to remember you

Most apps have to choose between speed and persistence. She Is is clever — it uses both a fast local cache and a reliable cloud backup, layered on top of each other.

💾
localStorage (layer 1, instant)

Saves test results directly in your browser. Zero network delay. Works offline. Data survives closing the tab but not clearing browser data. Used first, for speed.

☁️
Supabase database (layer 2, durable)

A PostgreSQL database in the cloud. Saves results when you're logged in. Lets you access your history from any device. Requires network connection.

🔍
The pattern: local-first, then sync

She Is always writes to localStorage first (instant, no failure risk), then attempts to sync to Supabase in the background. If the network is down or the user isn't logged in, the localStorage copy is still there. This pattern — called "local-first" — makes the app feel fast and resilient.

How a test scores your answers

Each test file (like test-hsp.html) contains all its own scoring logic. Here's the HSP scoring code, translated into plain English:

JS (test-hsp.html) const QUESTIONS = [ "Are you bothered by intense stimuli?", // 26 more questions... ]; let total = 0; answers.forEach(score => { total += score; // 1–7 per question }); const type = total >= 138 ? "high" : total >= 96 ? "medium" : "low";
Plain English
There are 27 questions stored in a list
Each answer is a number from 1 (not at all) to 7 (extremely)
Add up all the scores → total
Max possible total: 27 × 7 = 189
If total ≥ 138: "High HSP" (very sensitive)
If total ≥ 96: "Medium HSP"
Below 96: "Low HSP"

After scoring, the code looks up a description object using the type as a key — like opening a dictionary at the word "high" to find the full explanation.

The Outside World

Supabase, Netlify, and AI — the three external services that power She Is, and why each one is there.

Supabase: the invisible database

She Is doesn't own a server. Instead, it rents one from Supabase — a company that provides a ready-made database and authentication system via the internet.

Think of it like renting a storage unit instead of building a warehouse. You pay for the space; they handle the building, security, and plumbing.

assets/auth.js const sb = createClient( 'https://xagmrt...supabase.co', 'sb_publishable_Vryw...' ); async function saveTestResult( testName, resultType, resultData) { const user = await getUser(); if (!user) return null; await sb.from('test_results') .upsert({ user_id: user.id, ... }); }
Plain English
Connect to "our" Supabase project using its URL and a public key
The URL is the address of the database; the key is a badge that says "this is a She Is request"
saveTestResult is called after every test completion
First it checks: is the user logged in? If not, skip — no cloud save
.from('test_results') = "go to the table named test_results"
.upsert = "insert if new, update if already exists" (no duplicates)
🔑
Public key vs. secret key

The Supabase key in auth.js is marked sb_publishable_ — it's safe to be public. It only allows reading/writing data for the logged-in user. A secret key (like an AI API key) would give access to everything and must never appear in client-side code.

Magic link login: no passwords, ever

She Is uses "passwordless authentication." When you enter your email, Supabase sends you a link. Click the link → you're logged in. The link is your temporary password, delivered to your email.

1
You enter your email on login.html

The code calls sb.auth.signInWithOtp({ email }) — OTP stands for "one-time password"

2
Supabase sends you an email

The email contains a unique link valid for 1 hour. She Is has a custom email template for this (email-template-magic-link.html)

3
You click the link in the email

Your browser opens the app with special tokens in the URL. Supabase JS library detects them.

4
Session established — you're logged in

Supabase saves a session token in your browser. Every future request to the database includes this token automatically.

The Smart Tricks

Patterns worth stealing — the elegant decisions baked into She Is that you can request from any AI coding agent.

Trick #1: CSS Custom Properties as a design system

She Is defines all its colors and fonts in one place, then uses variable names everywhere else. Change the name's value once — every element that uses it updates automatically. It's like a global search-and-replace that runs in real time.

css/style.css :root { --c-primary: #33185c; --c-background: #f5f0ea; --c-secondary: #8faf8a; } /* Used throughout the app: */ button { background: var(--c-primary); } h1 { color: var(--c-primary); }
Plain English
:root { } = "define variables for the whole document"
--c-primary: #33185c = "name this purple color 'primary'"
var(--c-primary) = "use whatever color is named 'primary'"
To change the brand color everywhere: edit ONE line in :root
This is called a CSS custom property or CSS variable
Tailwind config.js extends this — Tailwind uses the same variables
🎯
How to use this when prompting AI

When asking AI to add a new UI element to She Is, say: "Use the existing CSS custom properties — reference var(--c-primary) for the brand color, var(--c-background) for backgrounds. Don't hardcode hex values." This keeps new elements consistent with the design system.

Trick #2: Upsert — insert or update in one move

When saving test results to Supabase, She Is uses an "upsert" operation. This is a clever database command that means: if a record for this user + this test already exists, update it. If not, create it.

This prevents duplicate results piling up in the database every time someone retakes a test. It's the database equivalent of "overwrite if exists."

assets/auth.js sb.from('test_results') .upsert({ user_id: user.id, test_name: testName, result_type: resultType, result_data: resultData, completed_at: new Date().toISOString() }, { onConflict: 'user_id,test_name' });
Plain English
Go to the test_results table in the database
Try to insert this new row of data
onConflict: 'user_id,test_name' = "if this user already has a result for this test..."
...then UPDATE the existing row instead of creating a duplicate
Result: each user has exactly one result per test, always the latest

Trick #3: Screenshot your own HTML to make a shareable card

She Is's beautiful result cards aren't just visual — users can download them as PNG images and share on social media. The trick? html2canvas — a library that takes a screenshot of any HTML element on the page and converts it to a downloadable image.

This is like the browser taking a photo of itself. No server, no image editing software needed.

assets/result-download.js async function downloadCard(elementId) { const el = document .getElementById(elementId); const canvas = await html2canvas(el, { scale: 2, // 2x for retina sharpness useCORS: true }); const link = document.createElement('a'); link.download = 'my-result.png'; link.href = canvas.toDataURL(); link.click(); // triggers download }
Plain English
Find the HTML element that contains the result card
html2canvas renders it onto an invisible canvas (like a paint surface)
scale: 2 = render at double resolution for crisp images on retina screens
canvas.toDataURL() converts the canvas to a PNG encoded as a text string
Create an invisible link element pointing to that PNG
Programmatically click it — this triggers the browser's file download
