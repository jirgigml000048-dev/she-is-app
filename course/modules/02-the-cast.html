Meet the Cast

Every file has a role. Here's who does what — and why it matters when you want to change something.

Think of the codebase as a theatre backstage

A theatre performance looks seamless on stage, but backstage there are distinct departments: lighting, costumes, sound, props, script. Each department has a clear responsibility, and they hand things off to each other on cue.

She Is works the same way. Different files have different jobs. When you know who does what, you can find the right file to change — instead of guessing.

How shared components work

She Is uses a clever pattern to share the navigation header across all pages without copying and pasting the same HTML everywhere. Here's how it works:

HTML <div id="app-header" data-back="true"></div> <script src="assets/header.js"></script>
What this means
Leave an empty placeholder div with id="app-header"
Then load the header.js script
header.js finds that div by ID and fills it with navigation HTML
data-back="true" tells header.js to show a back arrow on this page
Result: every page gets the same header, from one source file
🎯
Why this matters when steering AI

If you want to change the navigation — add a new menu item, change the logo — you change one file (assets/header.js) and every page updates automatically. If you tell AI to "add a notification bell to the header," it should edit header.js, not every individual page. If the AI starts editing each page individually, redirect it.
