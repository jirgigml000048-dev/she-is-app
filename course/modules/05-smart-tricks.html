The Smart Tricks

Patterns worth stealing — the elegant decisions baked into She Is that you can request from any AI coding agent.

Trick #1: CSS Custom Properties as a design system

She Is defines all its colors and fonts in one place, then uses variable names everywhere else. Change the name's value once — every element that uses it updates automatically. It's like a global search-and-replace that runs in real time.

css/style.css :root { --c-primary: #33185c; --c-background: #f5f0ea; --c-secondary: #8faf8a; } /* Used throughout the app: */ button { background: var(--c-primary); } h1 { color: var(--c-primary); }
Plain English
:root { } = "define variables for the whole document"
--c-primary: #33185c = "name this purple color 'primary'"
var(--c-primary) = "use whatever color is named 'primary'"
To change the brand color everywhere: edit ONE line in :root
This is called a CSS custom property or CSS variable
Tailwind config.js extends this — Tailwind uses the same variables
🎯
How to use this when prompting AI

When asking AI to add a new UI element to She Is, say: "Use the existing CSS custom properties — reference var(--c-primary) for the brand color, var(--c-background) for backgrounds. Don't hardcode hex values." This keeps new elements consistent with the design system.

Trick #2: Upsert — insert or update in one move

When saving test results to Supabase, She Is uses an "upsert" operation. This is a clever database command that means: if a record for this user + this test already exists, update it. If not, create it.

This prevents duplicate results piling up in the database every time someone retakes a test. It's the database equivalent of "overwrite if exists."

assets/auth.js sb.from('test_results') .upsert({ user_id: user.id, test_name: testName, result_type: resultType, result_data: resultData, completed_at: new Date().toISOString() }, { onConflict: 'user_id,test_name' });
Plain English
Go to the test_results table in the database
Try to insert this new row of data
onConflict: 'user_id,test_name' = "if this user already has a result for this test..."
...then UPDATE the existing row instead of creating a duplicate
Result: each user has exactly one result per test, always the latest

Trick #3: Screenshot your own HTML to make a shareable card

She Is's beautiful result cards aren't just visual — users can download them as PNG images and share on social media. The trick? html2canvas — a library that takes a screenshot of any HTML element on the page and converts it to a downloadable image.

This is like the browser taking a photo of itself. No server, no image editing software needed.

assets/result-download.js async function downloadCard(elementId) { const el = document .getElementById(elementId); const canvas = await html2canvas(el, { scale: 2, // 2x for retina sharpness useCORS: true }); const link = document.createElement('a'); link.download = 'my-result.png'; link.href = canvas.toDataURL(); link.click(); // triggers download }
Plain English
Find the HTML element that contains the result card
html2canvas renders it onto an invisible canvas (like a paint surface)
scale: 2 = render at double resolution for crisp images on retina screens
canvas.toDataURL() converts the canvas to a PNG encoded as a text string
Create an invisible link element pointing to that PNG
Programmatically click it — this triggers the browser's file download
